The folder `.glugent/` is a Glugent project that the repository uses on itself. Its config is the root `glugent.config.json`.

- Target files live in `.glugent/targets/agents/` (`*.agent.ggen.json`) and `.glugent/targets/docs/` (`*.doc.ggen.json`); sections live in `.glugent/sections/`.
- It is laid out like `examples/09-team`. Each target names one root section and nothing else (plus `output` for a document). The root sections mirror the targets, in `sections/roots/agents/` and `sections/roots/docs/` with the same names, and each holds everything its target says: its own values in `defaults` (`ROLE`, `MISSION`), its own text, and the pieces it includes.
- The pieces live in `sections/library/`: `parts/` (`identity`, the bundles `glugent-reference` and `repo-handbook`, and `project-discovery`), the topics in `glugent/` (how Glugent works) and `repo/` (how this repository works), and `common/h1`, `h2` and `h3` for headings. They are included by the end of their id (`parts/identity`, `glugent/cli`), which stays unique. Every heading is written as `{{ REF BEGIN common/h2 | HEAD="Title" }}` … `{{ REF END common/h2 }}`, and agents include `parts/identity` with `REF-OVERRIDE` so their `ROLE` and `MISSION` reach it.
- The agents `glugent-agent-builder`, `glugent-developer` and `glugent-helper` are built from them, and so are the documents: `README.md` and `CONTRIBUTING.md` (the `readme` and `contributing` targets) and the README that npm shows for each published package, `packages/cli`, `packages/core` and `packages/schemas` (the `package-cli`, `package-core` and `package-schemas` targets, from `sections/roots/docs/packages/`). These files are generated: change the text in the sections, never in the files, then run `npm run docs:build` and commit the result. The package READMEs link with absolute URLs, because npm does not resolve links relative to the repository.
- The MIT `LICENSE` is a document too: the `license` target writes it to the root, and `package-cli-license`, `package-core-license`, `package-schemas-license` and `package-vscode-license` write the same `roots/docs/license` into each package, because npm only packs a `LICENSE` from the package's own folder. The copyright holder is the config prop `AUTHOR`.
- `npm run targets:build` builds everything; `npm run docs:build` builds only the documents. Agents that are not documents are written to `/agents`, which is git-ignored.
- `npm run targets:validate` checks the project, and CI fails when a committed document differs from what the build produces (`npm run docs:check`).
